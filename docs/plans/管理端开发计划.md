# 主机管理端开发计划

日期：2026-11-08。范围：同一个 APK、同一个 app 模块；主机手机负责本地管理，普通客户端仍通过局域网访问主机。

## 目标与入口

MainActivity 的“开启主机”进入 HostActivity，保留主机启停和地址展示，并在同一页面增加数据概览、信息管理、用户查询、操作记录四个栏目。使用客户端既有 Material 组件、配色、中文文案和表单校验。管理栏目切换、详情和确认弹窗不启动其他 Activity，不触发主机停止。

管理能力属于持有主机手机的操作者，不由昵称决定，不创建远程管理员 token 或管理 HTTP 接口。请妥善保管主机手机；本阶段不增加应用锁。主机停服时也能查看和管理本地数据；退出前台仍停止网络监听，重新进入需手动开启。

## 功能与验收

| 功能 | 内容 |
| --- | --- |
| 主机控制 | 保留运行状态、启停、地址刷新和前台提示 |
| 概览 | 全量统计用户、帖子（含删除）、未删除的待解决/已完成/已关闭、待处理申请及已删除数，不能用前 100 条列表估算 |
| 信息管理 | 包括 CLOSED 和软删除在内的所有帖子，按标题、类型、分类、状态筛选；查看文字和图片 |
| 管理删除 | 可软删除 OPEN、RESOLVED、CLOSED 帖，必填 2～100 字原因；已删除不能重复操作 |
| 管理关闭 | 仅 OPEN 帖允许关闭，填写 2～100 个字符原因；有明确确认提示 |
| 用户查询 | 按昵称或完整用户 ID 查找，显示 ID、昵称、发布/申请数，可查看该用户的发布和申请状态 |
| 操作记录 | 区分关闭/删除，查看对象、标题、原因和主机时间；按时间和 ID 倒序 |

管理关闭在一个公共事务中完成：帖子 CLOSED、全部 PENDING 申请 REJECTED（note 为“管理员关闭信息：原因”）、写入 admin_actions。已处理的申请不变；关闭操作不能修改已完成/已关闭的帖子；删除操作可标记这些帖子，但不改变已完成交接的结果。不能替用户确认交接。关闭后的帖子从公开列表隐藏，但发布者和相关申请人的原记录仍可查。

不安排永久删除、恢复关闭帖子、编辑他人内容、封禁用户、发布前审核、举报、远程管理、后台保活。用户身份当前允许重新创建，不承诺通过简单封禁阻止同一人。

## 数据与实现

- 新增 data/HostAdminRepository，复用 AppDbHelper、PostDao、ClaimDao、DatabaseLock；页面不直接执行 SQL。
- 数据库支持 1→3、2→3 非破坏升级；新增 admin_actions、posts.is_deleted/deleted_at、管理记录 action 及相关索引；不删表、不重建数据库、不清空 token、hostId、帖子或图片。
- admin_actions：id、post_id（外键）、post_title（操作时快照）、reason、created_at、action（CLOSE/DELETE）。
- 新增 ui/HostAdminPanel，嵌入 activity_host；读写和图片解码均在后台线程。
- 管理记录按最新 100 条显示 hasMore 提示；用户可缩小信息/用户查询条件，本阶段不实现分页。
- 用户摘要不读取或展示 token_hash；用户申请列表不展示 proof/contact，只显示关联帖子、状态及处理说明。
- 所有 SQL 查询使用绑定参数；管理员关闭必须在事务内重新检查最新状态，防止与用户确认、取消或发布者关闭互相覆盖。
- 页面离开后不向旧页面回调；关闭结果不确定时先刷新帖子或操作记录，不自动重发。
- 关闭/删除原因在关闭弹窗前保存，旋转或切后台后再次打开同一帖时可恢复。

## 分工与顺序

1. A：数据库版本 1/2→3 迁移及本地管理数据入口。
2. B：关闭事务、相关申请联动、与已有状态操作的竞争检查。
3. 前端：沿用用户端样式完成同页管理栏目、列表、详情、原因输入和反馈。
4. 联调：先验证旧数据升级，再验证本地管理和远程客户端看到相同状态，确认切换栏目不影响 ping。

本次实现与测试状态以管理端验收清单为准，已有前端 PR 的通过记录不代表管理端已验收。

## 管理员软删除补充

在管理帖子详情提供“删除信息”，对未删除的三种状态均可使用，填写原因并再次确认；暂不恢复或物理清理。关闭与删除是两个独立操作。

删除与 pending 申请拒绝、DELETE 操作日志在同一事务中完成。若帖子原为 OPEN，则变成 CLOSED；原 RESOLVED/CLOSED 保留原业务状态。已 ACCEPTED/REJECTED/CANCELLED 的申请不改写，历史申请的标题显示“该信息已被管理员删除”，并带 postDeleted=true。

普通 PostDao.get/list 排除软删除记录，包括公开列表和我的发布；原详情 URL 返回 404，用户端刷新时清空旧内容；ImageStore 的公开图片读取也排除软删除。管理查询通过单独的本地方法读取原内容和图片，不对 HTTP 开放。申请历史保留关联行，界面显示已删除占位并禁用原信息详情按钮。

管理列表“全部”含已删除，新增“已删除”筛选；其他状态筛选仅查询未删除帖子。概览总帖子数含已删除，其他状态数量排除已删除，单列已删除数。旧管理日志 action 默认为 CLOSE，新删除日志为 DELETE。删除原因保存逻辑与关闭一致。
