# 校园失物招领 App 手机局域网接口约定

版本：0.2，2026 年 10 月 22 日。本文件替代上一版独立服务器设计，供开发人员 A 和 B 共用。这里只制定计划和接口，尚未编写或验证 App 实现。前端详细计划仍按约定留到下周。

## 一 运行方式

一个 Android Studio 工程生成同一个 APK。演示时三台手机连接可互访的同一局域网：一台选择“开启主机”，另外两台选择“连接主机”。主机手机负责 HTTP 服务、数据库和照片，客户端负责发请求和显示结果。

客户端填写主机当前地址，例如 http://192.168.1.20:8080。主机没有固定公网地址，不需要电脑开服务器。电脑只用于开发、安装和调试。

主机专用页面前台保持亮屏，退出或进入后台时停止监听；重新开启后仍使用原数据库。第一版不做后台保活、自动发现、主机迁移、自动同步和离线操作。主机 App 被结束时，客户端暂时不能使用。

所有数据集中在这一台主机上。任意另一台手机开启主机都会得到另一套独立数据，不会自动继承之前那台的数据。只换网络、普通重启不会删除原数据；卸载或清空主机 App 数据会删除记录。

## 二 技术与分工

| 部分 | 选择 | 负责人 |
| --- | --- | --- |
| 工程和界面 | Android Studio，Java，XML，同一个 app 模块 | 全员，正式界面计划下周制定 |
| 手机 HTTP 服务 | NanoHTTPD 核心库 | A |
| 数据库 | SQLiteOpenHelper，三张 SQLite 表 | A 管建表和公共工具，B 管业务 SQL |
| 网络请求 | HttpURLConnection 和 ExecutorService | A 写通用请求，B 包装业务方法 |
| JSON | JSONObject 和 JSONArray | 全员统一字段 |
| 图片 | 单张 JPEG，Base64 随发布请求发送 | A 提供工具，B 接入发布 |
| 身份 | 昵称进入，随机 token 识别用户 | A |
| 失物业务 | 发帖、搜索、申请、处理和完成 | B |

NanoHTTPD 是可嵌入 Java 应用的小型 HTTP 服务库，项目说明包含 Android 使用场景，参见 [项目官方说明](https://github.com/NanoHttpd/nanohttpd)。这里只嵌入核心库，不启动其独立服务器项目，也不照搬示例中的 Maven 工程。

SQLiteOpenHelper 是 Android 自带的数据库 API；官方通常建议复杂应用使用 Room，本课设只有三张表，选择直接使用 SQLiteOpenHelper 来减少额外工具，参见 [Android SQLite 文档](https://developer.android.com/training/data-storage/sqlite)。

## 三 简化后的范围

保留：昵称进入、寻物与招领、每帖最多一张照片、搜索和分类、我的发布、认领或拾获线索、我的申请、收到的申请、确认归还、拒绝、取消、关闭和站外找回。

第一版不做：账号密码、管理员、评论、聊天、收藏、举报、推送、地图、自动匹配、帖子修改删除和复杂分页。信息填写错误时关闭后重新发布。

两种类型：LOST 是“我丢了东西”，FOUND 是“我捡到了东西”。LOST 的申请表示提供拾获线索，FOUND 的申请表示申请认领。发布者读取申请联系方式后沟通，线下完成交接再点确认完成。

## 四 连接和身份

### 连接流程

1. 主机显示局域网地址和运行状态，端口默认 8080。
2. 客户端请求 GET /api/ping，核对 app 为 campus-lost-found、protocolVersion 为 2。
3. 读取 hostId。若与本机保存的主机标识不同，先清除原 token 和旧列表。
4. 有旧 token 时请求 GET /api/session；有效则恢复身份，401 时重新填昵称。
5. 首次连接时 POST /api/sessions 创建身份，保存 token、memberId、nickname、hostId 和基础地址。
6. 后续需要身份的请求加 Authorization: Bearer <token>。

昵称可以重复，不能用昵称当主键。请求体里不接收操作者 userId、memberId、ownerId 或 applicantId。主机从 token 找到真实用户。第一版 token 不过期，主机重启后继续有效；客户端清空本机数据会失去身份，不做身份找回。

### 网络配置

主机监听局域网可访问地址，客户端不能用自己的 localhost 访问另一台手机。不要把热点 IP 写死。首先实测同 Wi-Fi 下两台真机能连通；若网络启用了设备隔离，换成允许互访的路由器或经测试可用的手机热点。

应用声明 INTERNET 和 ACCESS_NETWORK_STATE，课设演示版明确允许局域网 HTTP。网络读写放后台线程，完成后切回主线程更新界面，参见 [Android 网络连接文档](https://developer.android.com/develop/connectivity/network-ops/connecting) 和 [网络安全配置](https://developer.android.com/privacy-and-security/security-config)。

若 target SDK 为 37 或以上，局域网访问按官方要求声明并运行时申请 ACCESS_LOCAL_NETWORK，主机接收连接和客户端发起连接都需要处理；目标不超过 36 则依对应版本要求配置。详细规则见 [Android 局域网权限说明](https://developer.android.com/privacy-and-security/local-network-permission)。A 在工程初始化时统一处理这些配置，不留给前端猜测。

## 五 共同请求和返回格式

基础地址以主机当前显示为准。业务路径以 /api 开头，图片路径以 /images 开头。普通请求统一为 UTF-8 JSON；没有请求参数的 POST 可以传空对象 {}。

成功 HTTP 200，固定包装：

```json
{
  "success": true,
  "message": "ok",
  "data": { "id": 101 }
}
```

失败返回对应 HTTP 状态以及固定 JSON：

```json
{
  "success": false,
  "message": "你已经提交过申请",
  "data": null
}
```

| HTTP 状态 | 含义 |
| --- | --- |
| 400 | 参数缺失、字段格式错误、非法分类或状态 |
| 401 | token 缺失或无效 |
| 403 | 有身份但不是有权操作的人 |
| 404 | 资源或图片不存在，未知接口也返回此错误 |
| 409 | 重复申请、状态不允许或操作冲突 |
| 413 | 请求体或图片超出限制 |
| 500 | 主机内部错误，不返回堆栈或磁盘路径 |

所有 ID 是 JSON 整数，Java 使用 long；时间用 Unix 毫秒整数，例如 createdAt 取主机 System.currentTimeMillis()，客户端负责格式化显示。帖子发生的具体时间写入描述即可，不再另做日期选择字段。

列表统一 data 为 {items, hasMore}。最多返回最新 100 条，按 createdAt 倒序、id 倒序。先取 101 条判断 hasMore，再返回前 100 条；hasMore 为 true 表示本次只显示最新部分。课设不实现翻页，但数据库仍保留全部记录。空结果 items 为 []、hasMore 为 false。

分类固定六项：CARD 证件卡片，ELECTRONICS 电子产品，KEYS 钥匙，BOOKS 书籍资料，DAILY 生活用品，OTHER 其他。直接用常量，无需分类接口和字典表。

## 六 共用数据对象

### Member

id 为用户 ID，nickname 为昵称。对外只返回这两个字段，不返回 token 摘要。

### Post

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| id | long | 帖子 ID |
| type | String | LOST 或 FOUND |
| title | String | 标题 |
| description | String | 描述，详情和列表都返回，减少两套对象 |
| category | String | 固定分类 |
| location | String | 校园地点 |
| imagePath | String 或 null | 相对图片路径 |
| status | String | OPEN、RESOLVED 或 CLOSED |
| owner | Member | 发布者 ID 和昵称 |
| createdAt | long | 发布时间毫秒 |
| updatedAt | long | 最近更新时间毫秒 |

### Claim

id、postId、postTitle、postType、postStatus、applicant、proof、contact、status、note、createdAt、updatedAt。其中 applicant 为 Member；note 尚未处理时为 null。proof、contact 只允许在双方有权限的申请接口中出现。

帖子不删除，因此申请可以通过关联 posts 获得标题、类型和状态，无需额外的历史快照字段。

### 状态变化

| 动作 | 允许条件 | 结果 |
| --- | --- | --- |
| 发布 | 身份有效、字段合法 | 帖子 OPEN |
| 申请 | 别人的 OPEN 帖，自己没有历史申请 | 新申请 PENDING |
| 确认交接 | 发布者操作，帖子 OPEN，申请 PENDING | 帖子 RESOLVED，目标 ACCEPTED，其他 PENDING 变 REJECTED |
| 拒绝 | 发布者操作，帖子 OPEN，申请 PENDING | 目标 REJECTED，帖子不变 |
| 取消 | 申请人操作，帖子 OPEN，申请 PENDING | 目标 CANCELLED，帖子不变 |
| 站外完成 | 发布者操作，帖子 OPEN | 帖子 RESOLVED，全部 PENDING 变 REJECTED |
| 关闭 | 发布者操作，帖子 OPEN | 帖子 CLOSED，全部 PENDING 变 REJECTED |

关闭和完成都不支持重新开启。同一用户对同一帖终身一条申请，拒绝或取消后不重新提交。确认同一条已 ACCEPTED 且帖子 RESOLVED 的申请可返回当前结果，其他重复状态操作返回 409。

## 七 A 负责的四个接口

### A01 主机检测

GET /api/ping，无需身份。

```json
{
  "success": true,
  "message": "ok",
  "data": {
    "app": "campus-lost-found",
    "protocolVersion": 2,
    "hostId": "主机初始化时生成并持久化的随机ID"
  }
}
```

### A02 昵称进入

POST /api/sessions，无需身份。请求 nickname，去首尾空白后为 1～20 字符。每次创建新的独立身份，不因昵称相同自动登录已有用户。

```json
{ "nickname": "小林" }
```

```json
{
  "success": true,
  "message": "ok",
  "data": {
    "member": { "id": 1, "nickname": "小林" },
    "token": "主机生成的足够长的随机字符串",
    "hostId": "与ping相同的主机标识"
  }
}
```

token 使用安全随机值，主机保存 SHA-256 摘要，不记录原 token 到日志；客户端保存原 token。不要只返回用户 ID 然后允许随意冒充他人。

### A03 恢复本机身份

GET /api/session，需要 token，返回 data 为 {member, hostId}，格式与上面一致但不重新返回或生成 token。身份无效返回 401。

### A04 读取图片

GET /images/{fileName}，无需身份。存在时 HTTP 200，Content-Type: image/jpeg，响应体为图片字节，不加 JSON 包装。

fileName 只能是主机生成的文件名，映射到 App 专用图片目录，禁止路径穿越、列出目录和读取任意文件。不存在返回 404 JSON 错误。

## 八 B 负责的十二个接口

### B01 发布信息

POST /api/posts，需要 token。

| 请求字段 | 要求 |
| --- | --- |
| type | LOST 或 FOUND，必填 |
| title | 2～40 字符，必填 |
| description | 5～500 字符，必填，包含时间和物品特征即可 |
| category | 六个固定分类之一，必填 |
| location | 2～60 字符，必填 |
| imageBase64 | 可选；未传或 null 表示无图；有值时为不带 data: 前缀的 JPEG Base64 |

```json
{
  "type": "FOUND",
  "title": "图书馆捡到一串钥匙",
  "description": "今天中午在二楼自习区捡到，请说明钥匙数量和挂件特征。",
  "category": "KEYS",
  "location": "图书馆二楼"
}
```

客户端图片压缩到最长边 800 像素内、目标 300 KB 内；主机验证 Base64 合法、可解码成 JPEG、解码数据不超过 500 KB。每个请求体总量最多 1 MB。错误图片返回 400，过大返回 413。

B 调用 A 的 ImageStore，成功后把随机文件名存入 posts。写库失败时删除本次新建图片，不能先返回成功再保存。不能让客户端指定物理路径或 ownerId。

成功 data 为 Post，status 初始 OPEN。

### B02 浏览和搜索

GET /api/posts，无需身份。可选参数 type、category、keyword、status。status 只允许 OPEN 或 RESOLVED，不传同时包含两者；CLOSED 只在我的发布中展示。keyword 去首尾空白后最多 40 字符，只匹配标题，空白表示不筛选。

成功 data 为 Post 的列表包装 {items, hasMore}。筛选先于条数限制；非法枚举返回 400，使用占位参数，关键词中的百分号和下划线按字面搜索。

示例：/api/posts?type=FOUND&category=KEYS&status=OPEN。

### B03 帖子详情

GET /api/posts/{postId}，无需身份。返回 data 为 Post，不包含申请证明和联系方式。CLOSED 帖也允许用 ID 查看，但页面要显示已关闭且不可申请。不存在返回 404。

### B04 我的发布

GET /api/me/posts，需要 token。可选 status 为 OPEN、RESOLVED、CLOSED，不传包括全部。成功 data 为 Post 的列表包装，只返回当前身份发布的记录，不接受 userId 参数。

### B05 提交认领或拾获线索

POST /api/posts/{postId}/claims，需要 token。proof 为 10～300 字符、contact 为 3～80 字符，必填。

```json
{
  "proof": "钥匙有三把，挂件上有一个蓝色小熊。",
  "contact": "微信 campus_test"
}
```

帖子不存在 404；申请自己帖子 403；非 OPEN 或重复申请 409。LOST 填拾获线索，FOUND 填特征证明。成功 data 为 Claim，status=PENDING、note=null。

### B06 我提交的申请

GET /api/me/claims，需要 token。可选 status 为四种申请状态之一。成功 data 为 Claim 的列表包装，只查当前申请人，包括联系方式和证明。

### B07 我某条帖子收到的申请

GET /api/posts/{postId}/claims，需要 token，且必须是该帖发布者。可选 status 同上。成功 data 为 Claim 的列表包装。无申请返回空数组，非发布者 403，不存在的帖子 404。

第一版没有独立申请详情接口，申请内容就在这两个有权限的列表中返回。公开列表不能通过参数切换为申请列表。

### B08 确认完成交接

POST /api/claims/{claimId}/confirm，需要 token，仅发布者，无参数，可传 {}。

要求帖子 OPEN、申请 PENDING。事务里把目标申请改为 ACCEPTED，note 为“已确认完成交接”；帖子 RESOLVED；其他 PENDING 变 REJECTED，note 为“物品已完成交接”。成功 data 为目标 Claim，其 postStatus 同时变为 RESOLVED。

同一条已 ACCEPTED 且帖子 RESOLVED 的申请重复确认返回当前结果；其他非法状态返回 409。无权限 403，不存在 404。

### B09 拒绝申请

POST /api/claims/{claimId}/reject，需要 token，仅发布者。请求 reason，2～100 字符，必填。

```json
{ "reason": "物品特征不匹配" }
```

要求帖子 OPEN、申请 PENDING，改为 REJECTED，note=reason，帖子不变。成功 data 为 Claim。重复操作或非法状态 409。

### B10 取消申请

POST /api/claims/{claimId}/cancel，需要 token，仅申请人，无参数。要求帖子 OPEN、申请 PENDING，改为 CANCELLED，note=null。成功 data 为 Claim。重复或非法状态 409。

### B11 站外找回或归还

POST /api/posts/{postId}/resolve，需要 token，仅发布者，无参数。要求 OPEN。把帖子变为 RESOLVED，所有 PENDING 申请变为 REJECTED，note 为“发布者已通过其他途径完成交接”，不产生 ACCEPTED 申请。成功 data 为 Post。非法状态 409。

### B12 关闭帖子

POST /api/posts/{postId}/close，需要 token，仅发布者，无参数。要求 OPEN。把帖子变为 CLOSED，所有 PENDING 变为 REJECTED，note 为“发布者已关闭信息”。成功 data 为 Post。非法状态 409。

B08 至 B12 每次成功写操作都更新相关记录 updated_at。B11 和 B12 必须与申请更新一起提交。

## 九 三张 SQLite 表

数据库只存在主机手机，客户端不直接打开主机数据库文件。

| 表 | 最小字段 | 约束 |
| --- | --- | --- |
| members | id INTEGER PRIMARY KEY AUTOINCREMENT；nickname TEXT；token_hash TEXT；created_at INTEGER | token_hash 唯一且非空；昵称不唯一 |
| posts | id INTEGER PRIMARY KEY AUTOINCREMENT；owner_id INTEGER；type TEXT；title TEXT；description TEXT；category TEXT；location TEXT；image_name TEXT 可空；status TEXT；created_at INTEGER；updated_at INTEGER | owner_id 引用 members；必填字段非空 |
| claims | id INTEGER PRIMARY KEY AUTOINCREMENT；post_id INTEGER；applicant_id INTEGER；proof TEXT；contact TEXT；status TEXT；note TEXT 可空；created_at INTEGER；updated_at INTEGER | UNIQUE(post_id,applicant_id)；引用 posts 和 members |

主机初始化生成 hostId 存在其私有 SharedPreferences 中，普通重启不变。外键在 AppDbHelper 中启用，不配置级联删除；本版没有物理删除接口。

建议索引：posts(owner_id)、posts(status,created_at,id)、claims(post_id,status)、claims(applicant_id,created_at,id)。数据量小，不额外做全文索引或缓存。

## 十 公共锁与事务

所有写操作都走同一个 DB_LOCK，包括创建身份、发帖、申请、确认、拒绝、取消、关闭和完成。锁由 A 的公共工具统一提供，在主机同一进程中使用。读查询也通过统一数据工具，避免读取尚未完成的一组业务更新。

在公共锁内开始 SQLite 事务，重新读取和检查当前状态，再修改，全部成功才标记提交。不要把 MySQL 的行锁语句照搬到 SQLite，也不要每个 Handler 自己建一把独立锁。

图片解码压缩等耗时工作尽量放在数据库锁外；图片对应数据库写入失败要清理本次文件。不能让图片处理堵住手机界面线程。

至少验证两个同时请求：确认两个不同申请时最多一条 ACCEPTED；提交与关闭同时发生时，CLOSED 帖上最终不能有 PENDING。3～5 台手机的课设演示不需要分布式锁和压力测试平台。

图片例子只需把 Post 的 imagePath 改为 /images/主机生成的文件名.jpg。客户端加载当前基础地址加相对路径。不要把 Base64 再放回查询响应，避免列表体积过大。

## 十二 三台手机的演示步骤

1. 手机甲选择开启主机，显示真实地址，并保持主机页面前台亮屏。
2. 手机乙、丙输入地址，检测通过后各自填昵称。
3. 乙发布招领信息，丙刷新列表后能看到。
4. 丙提交特征证明和联系方式。
5. 乙打开自己收到的申请，查看内容，模拟线下交接后确认完成。
6. 丙查看自己的申请变成 ACCEPTED，公开帖子状态变成 RESOLVED。
7. 再演示一条 LOST 寻物，申请内容改成拾获线索。
8. 主机停止后客户端请求能显示连接失败；甲重新开启后，原有数据和身份仍可使用。

前两步必须最先验证。主机模式运行在手机上会受到系统生命周期和现场网络影响，以实际三台手机连通测试为准，不承诺任意路由器和所有型号手机都未经测试可用。
