# 第一步：主机和 ping 测试

本步实现 A 的最小主机和 GET /api/ping。没有修改共同接口约定；完整网络客户端、数据库和昵称身份按后续步骤实现。

## 文件归属

- server：LanServer、ServerManager、HostIdentity。
- common：ApiConstants、JsonResponse、LanAddress。
- ui：临时 HostActivity；MainActivity 保留根包，提供入口。
- res/layout：activity_main.xml、activity_host.xml；文字放在 res/values/strings.xml。
- 构建配置仅增加 NanoHTTPD 核心库；清单加入网络权限、局域网 HTTP 和主机页面。

hostId 在手机私有 SharedPreferences 中生成并持久化，不依赖 IP。未新增数据库表。

## 两台真机验收

1. 两台手机连接同一可互访 Wi-Fi，或经实测可用的手机热点。
2. 在手机甲安装 debug APK，打开“进入主机测试”，点击“开启主机”。系统询问附近设备／局域网权限时允许。
3. 主机显示运行中，记下页面上的实际地址；有多个候选时核对系统设置中的 Wi-Fi／热点网段。
4. 保持甲在主机页面，用手机乙的浏览器访问“实际地址/api/ping”。不要用乙自己的 localhost。
5. 核对 HTTP 200 和以下 JSON，hostId 应是非空随机 ID：

```json
{
  "success": true,
  "message": "ok",
  "data": {
    "app": "campus-lost-found",
    "protocolVersion": 2,
    "hostId": "主机生成的随机ID"
  }
}
```

6. 连续点击启动不会重复监听。停止后乙应无法建立新连接；重新开启后可访问，hostId 不变。
7. 甲切到后台或返回上一页后停止监听，重新进入需要手动开启；旋转屏幕后也手动开启。
8. 关闭并重新打开 App，开启后 hostId 不变。卸载或清除应用数据不属于普通重启，会生成新标识。
9. 请求 /api/not-found，应返回 HTTP 404 和 success=false、message、data=null。
10. 在 SDK 37 或以上设备上拒绝权限，页面应提示授权且不启动；授权后可重新开启。

浏览器可能显示旧页面，停止测试时务必重新发起请求。真机互访、系统权限弹窗、热点兼容性需在实际手机上确认；编译通过不代表以上现场验收已经通过。

## 无法连接时

- 确认地址来自甲，协议为 http，端口为 8080，末尾为 /api/ping。
- 确认甲显示“运行中”，页面在前台，系统权限已授予。
- 暂时关闭影响路由的 VPN，核对两个设备处于同一可互访网段。
- 校园 Wi-Fi 可能启用设备隔离，换路由器或热点重试。
- 开启失败时查看页面显示的错误；端口占用时先关闭占用服务。

- debug APK 构建通过，输出 app/build/outputs/apk/debug/app-debug.apk。
- Android 设备测试包构建通过。LanServerInstrumentedTest 包含 5 个测试：ping 协议及标识重用、JSON 404、重复启停及释放端口、端口占用失败恢复、页面退出停止与手动重启。

- 设备测试尚未执行：当前没有连接真机，已有 API 36 模拟器因缺少硬件加速驱动无法启动。未安装或更改系统驱动。
- 两台真机互访、普通进程重启后的标识持久化、SDK 37 权限授权与拒绝行为仍需现场验收。
- 接入设备后，可在 Android Studio 运行 LanServerInstrumentedTest；也可运行 Gradle 的 :app:connectedDebugAndroidTest。
