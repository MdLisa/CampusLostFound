## 本轮修复

| 文件 | 改动及原因 |
| --- | --- |
| ui/HostActivity.java | 所有主机页面实例共用串行队列，旧页面停止在新页面启动之前执行，避免页面快速退出、重进或旋转时旧任务停掉新服务 |

| res/layout/activity_connect.xml、activity_business_debug.xml | 连接结果、身份和图片状态等临时输出不从旧页面自动恢复，避免重新验证时显示旧主机或旧照片的状态 |
| res/values/strings.xml | 增加重新查询与写操作结果未知的提示 |
| androidTest/.../BackendRecoveryInstrumentedTest.java | 增加实际公共工具的回归源码，见下文；本轮未执行 |

主机标识仍来自私有 host_config；原 token 摘要、帖子和申请保存在 SQLite，照片保存在 files/images。停止服务和普通重启都不清空它们。客户端断网保留凭据，401 才清除当前无效身份；切换基础地址或检测到不同 hostId 清除旧身份。

## 用户设备验收清单

先让主机甲和客户端乙、丙覆盖安装本次主程序 CampusLostFound.apk。无需卸载。甲始终保持主机页面前台；乙、丙分别使用自己的身份。请记录乙、丙用户 ID、甲的 hostId、一个带图帖子 ID 和申请 ID。

### 1 反复启停和页面重建

- [ ] 连续点击开启，主机只有一个监听，客户端 ping 正常。
- [ ] 点击停止后客户端查询失败；再开启后恢复。反复做 3 次，没有无故出现端口占用。
- [ ] 主机按 Home 或返回退出后停止；重新进入页面不会自动启动，手动开启后能连接。
- [ ] 开启过程中立即返回，再进入并开启；新服务不被旧页面延迟停止。
- [ ] 若设备允许旋转，主机页旋转后停止，新页面可手动开启，客户端再次连接成功。

离开页面后停止会在后台队列执行，不承诺点击返回的同一瞬间已经关闭所有连接。手动停止后不应继续接受新请求。

### 2 断网和恢复

- [ ] 乙临时断开 Wi-Fi，再点击查询；出现连接失败或超时提示，页面保持响应，随后按钮可继续使用。
- [ ] 恢复乙的网络，再查询能成功；用户 ID 不因断网自动改变，不需要新建昵称身份。
- [ ] 保持乙网络正常，甲停止主机，乙查询应失败；甲重启监听后，乙可重新查询原数据。
- [ ] 如更换 Wi-Fi，先让甲刷新地址；乙、丙填写当前地址重新检测，图像路径仍可正常读取。

连接和读取分别设置 5 秒超时，并非所有请求保证总计 5 秒结束。后台线程排队、连接建立与读取均可能影响总耗时。网络失败不会自动重复业务 POST。

注意：当前约定是“更换基础地址即清除旧身份”。即使仍是同一台主机，只要客户端改填了新地址，也需要新建身份，不能用旧昵称恢复原来的用户。这与同一地址下普通断网和重启保留身份不同。

### 3 主机 App 重启后的持久化

- [ ] 乙发布带图帖子，丙提交申请，记录帖子 ID、申请 ID、双方用户 ID 与 hostId。
- [ ] 甲停止主机并完全关闭 App，再打开、进入主机页并手动开启。使用原地址测试，不卸载、不清空数据。
- [ ] 乙、丙重新检测并恢复，双方用户 ID 与原来一致；hostId 不变。
- [ ] 原帖子文字和照片可查看，丙的申请仍在；乙可读取收到的申请及其证明和联系方式。
- [ ] 乙确认完成，丙刷新看到 ACCEPTED，公开帖子 RESOLVED；再次重启甲后这些状态不丢失。

覆盖安装通常保留数据。卸载、清空主机数据会删除整套主机记录；本项目不提供恢复和迁移功能。

### 4 请求中断、页面返回和重复操作

- [ ] 乙开始查询后立刻退出业务页，再进入；不会被旧回调覆盖当前结果。
- [ ] 如写操作期间断网、超时或退出页面，出现“上次写操作尚未确认结果”提醒。恢复后先查询实际记录，再决定是否重试。
- [ ] 发布重试前先看“我的发布”；提交申请后先看“我的申请”；确认、拒绝、取消等先看相关申请和帖子状态。
- [ ] 对已经 ACCEPTED 且帖子 RESOLVED 的同一申请重复确认仍成功；重复申请、重复关闭等非法状态按约定返回 409。
- [ ] 选图返回页面后重新验证身份，带图发布与详情照片继续可用；旋转导致页面重建后需重新选图。

取消回调和关闭页面不能撤销主机已经收到的写请求。发布接口没有防重复请求编号，因此无法保证网络中断后盲目重试只产生一条帖子。

### 5 更换主机与权限

这组建议最后用备用客户端测试，因为按约定切换地址会清除该客户端原身份。

- [ ] 备用客户端连甲取得身份，再连接另一台临时主机；须重新填写昵称，不沿用甲的用户身份，也不显示甲的旧查询结果。
- [ ] 同名昵称也只是新身份；切回甲后不能靠昵称找回先前身份。
- [ ] 丙不能读取乙帖子收到的申请，返回 403；公开帖子详情不出现申请 proof/contact。
- [ ] 无效 token 返回 401；界面要求返回连接页重新进入，不能继续发送需要身份的操作。
- [ ] 若有需申请局域网权限的设备，拒绝授权时有提示，授权后可以重新连接。Android 12 不弹此权限对话框，不能据此验证新系统权限分支。

相同地址对应的主机 hostId 改变时也会清除旧身份；普通设备验收不要求清空主要演示主机的数据来制造该情况。

### 6 三台设备完整演示

- [ ] 甲为主机，乙发布 FOUND 带图帖子，丙浏览、看详情、提交特征与联系方式，乙查看收到的申请并确认，双方状态一致。
- [ ] 再演示 LOST，申请内容作为拾获线索；验证取消、拒绝、关闭或站外找回分支。
- [ ] 最后甲停止再开启，乙、丙身份和上述记录仍可恢复。

两个不同申请同时确认、提交申请与关闭同时发生的并发场景，已有 BusinessFlowTest 源码。若要手工覆盖两个申请人竞争，除主机和发布者外还需要两个独立申请人客户端；不把普通三台设备顺序演示当作并发验收。

## 回归测试源码与本轮检查

新增 BackendRecoveryInstrumentedTest，包括：

1. 启停同步锁被占用时，状态快照仍可返回。
2. 主机 Activity 重建后停止监听，新页面可再次启动并响应 ping。
3. 同一公共事务中修改成员并插入帖子后主动抛异常，验证两个修改均回滚。
4. 通过真实 HTTP 创建两名成员、图文帖子、申请并确认；停止监听、关闭并重开 SQLite 文件后，验证 hostId、原 token、帖子状态、申请与 JPEG 字节；同时检查 401、403、409 和图片 404。

该源码只在专用开发设备手动执行。测试会启停应用主机，创建测试记录，并在结束时按本次 ID 清理；不清空其他记录和配置。它不是进程强杀或真实跨手机网络测试的替代。

本轮主程序构建、lint 静态检查和设备测试源码编译通过；lint 0 错误，2 个已有模板颜色未使用警告。没有运行上述用例、原有 BusinessFlowTest、模拟器或实际设备测试。真实断网、旋转、进程重启、多设备和权限行为均以用户设备验收为准。

## 交给 B 和前端

- 16 个接口均已接入；URL、字段、错误状态与隐私规则以共同接口约定为准。
- 主机页复用 ServerManager 和公共启停顺序；接口操作使用 LostFoundApi(new LanApiTransport(client))，不另建数据库、HTTP 或公共锁。
- 每个可见页面创建自己的 LanApiClient，停止页面时 close；再次进入先连接检测或验证身份。网络回调在主线程，压缩和数据库仍放后台。
- JSON 成功 data 为对象。LostFoundApi 成功回调带完整包装；HTTP 失败保留状态和错误包装，error=null；本地与网络失败 code=0、response=null、error 非空。
- 图片复用 ImageCompressor.compress 与 client.loadImage；最长边 800、客户端目标 300 KB、主机上限 500 KB、整请求上限 1 MB。
- 前端也应提示写操作结果可能未知，先查询确认，不自动重发。401 引导重新进入，403/409 展示业务原因，普通网络失败保留身份。
- 当前 ui 下仍是临时主机、连接和业务联调页面；正式前端开发尚不属于本轮工作。

安装主程序：当前聊天工作区“安装包/CampusLostFound.apk”。所有端都覆盖安装，不安装 app-debug-androidTest.apk。第六步逐项验收后再确认后端 A 收尾；本轮未进行 Git 提交或推送。
