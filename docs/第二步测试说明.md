# 第二步：客户端连接检测与公共网络工具

## 本步范围

复用第一步的主机启停、HTTP 配置和 ping 接口，加入 App 内的客户端连接检测。接口路径、字段和协议版本不变。昵称身份、数据库及业务页面留到后续步骤。

- api/ServerAddress：校验并统一基础地址格式。
- api/ClientConnectionStore：保存最近地址、主机标识，并统一清除旧身份。
- api/LanApiClient：GET、POST、UTF-8 JSON、Bearer token、超时、错误和主线程回调。
- ui/ConnectActivity：临时连接检测页。
- res/layout/activity_connect.xml：连接页布局；文字统一放在 strings.xml。
- MainActivity 保留在根包，增加连接主机入口。

新写入的文件使用 Windows CRLF 换行，与当前 core.autocrlf=true 配置配合。没有修改 Git 配置、暂存文件、提交或推送。

## 真机测试（由用户执行）

1. 两台手机安装最新 APK，接入可互访的同一 Wi-Fi 或热点。
2. 甲选择“开启主机”，启动后保持主机页面在前台。
3. 乙选择“连接主机”，输入甲页面显示的完整地址，例如 http://192.168.137.99:8080；不加 /api/ping。这是示例，每次以实际地址为准。
4. 点击“检测并连接”，如有局域网／附近设备权限弹窗，选择允许。
5. 乙应显示“连接成功”，并显示 campus-lost-found、协议版本 2 和与甲 ping 一致的 hostId。
6. 关闭并重新打开乙的 App，连接页应回填最近使用的地址，点击按钮重新检测。
7. 停止甲的主机服务后，乙再次检测应显示失败。重新开启甲后，乙重试成功，hostId 不变。
8. 输入错误 IP 或端口应显示连接失败或超时，页面不应卡住；可以返回退出。连接和读取超时分别为 5 秒，不保证整个请求总共只耗时 5 秒。
9. 输入空地址、错误协议、缺少端口、带 /api/ping 的地址时，应提示格式错误；末尾单个 / 可以接受。
10. 乙请求期间退出连接页面，应取消该次页面回调；重新进入后可以再次检测。
11. 有 Android 17 或以上设备时，测试拒绝局域网权限后的提示，以及允许权限后重试。
12. 条件允许时，对一个返回 HTTP 200 的普通网页地址发起检测，应报数据格式或应用协议不匹配，而不是显示成功。

身份尚未实现，本步无法通过界面验收 token 恢复与清除；第三步接入身份后补测“更换地址／hostId 清除旧身份”。本步已实现对应清除逻辑。当前没有业务列表缓存；前端后续切换主机时需清空列表并重新请求。

## 公共 Java 调用方式

每个调用页面创建自己的 LanApiClient 实例，复用同一份 ClientConnectionStore。先调用 connect(address, callback)，成功后调用 request：

```java
LanApiClient client = new LanApiClient(context);

// connect 的成功回调中，data 就是 ping 的 data 对象。
client.connect("http://实际主机IP:8080", callback);

// 由 B 在后续业务中调用，尚未实现的接口当前会返回 404。
client.request("GET", "/api/posts", null, callback);
client.request("POST", "/api/posts", postJson, callback);
```

- callback 实现 onSuccess(JSONObject data) 和 onFailure(LanApiClient.ApiError error)，两者均在主线程调用。
- 成功回调只返回包装中的 data，不再由界面重复解析 success。
- ApiError.statusCode 为 HTTP 状态码；本地参数、网络及协议错误为 0。message 可直接展示。
- 方法返回 RequestHandle；页面停止时 cancel，销毁时 client.close。取消只抑制回调，不保证已送达服务端的操作被撤销。
- 关闭的实例不能复用，继续调用会抛出 IllegalStateException；新页面重新创建实例。
- 只支持 GET、POST，相对路径必须以 /api/ 开头。GET 参数需由调用方正确 URL 编码，POST 没有参数时传 null 或空对象，实际发送 {}。
- 自动拒绝 HTTP 重定向，避免把请求意外送往其他地址；JSON 响应读取上限为 2 MB。
- ping 和创建身份请求不携带旧 token；其他请求会从公共配置读取 token。第三步会沿用 client_connection 配置中的 token、member_id、nickname。
- 修改基础地址会立即清除旧身份；检测到不同 hostId 也会清除。每次重新检测会使旧请求失效，旧主机的晚到响应不会作为当前主机结果回调。
- 普通 App 重启保留地址及 hostId，但需要再次 ping 验证后才能发业务请求。
- 数据库、昵称登录和业务接口没有在本步提前实现。
