## 准备与升级

- [ ] 使用专用测试主机；升级前保留一份旧版 APK 和必要测试数据。
- [ ] 在旧版主机创建用户、图文帖子、待处理及已处理申请；用同签名新版 APK 覆盖安装，不卸载、不清空数据。
- [ ] 升级后启动主机成功，旧昵称身份、hostId、帖子、图片及申请均保留。
- [ ] 首次全新安装也能启动主机并进入空管理列表。

## 页面与连接

- [ ] 从开启主机入口进入，主机控制与四个管理栏目可使用。
- [ ] 主机运行时反复切换栏目、查看详情、打开/取消关闭弹窗，客户端始终能访问 /api/ping。
- [ ] 返回桌面会停止主机；回到主机页面后可手动重新开启。
- [ ] 停服时管理本地数据仍可使用，界面不会误显示服务运行中。
- [ ] 深色、大字号、小屏和键盘弹出时控件可见，长列表及弹窗可滚动。
- [ ] 管理关闭原因输入后切后台或旋转，再次打开同一帖子可恢复。

## 查询

- [ ] 概览与数据库实际总数一致，超过 100 条时仍是全量统计。
- [ ] 信息列表含已关闭帖子，类型、分类、状态和标题组合筛选正确。
- [ ] 标题中的 %、_ 按普通字符匹配；空列表与查询失败有不同提示。
- [ ] 详情能看文字和本地照片，缺失图片不影响文字与操作。
- [ ] 按用户昵称及完整 ID 查找，重名用户通过 ID 区分。
- [ ] 用户发布/申请记录归属正确，不显示 token 或 token_hash；管理用户申请摘要不显示证明和联系方式。
- [ ] 超过 100 条显示限制提示，不能误称已经显示所有记录。

## 管理关闭与客户端同步

使用主机 A、发布者 B、申请人 C；有条件再加申请人 D。

- [ ] B 发布 OPEN 帖，C（及 D）申请，A 能查看该帖子。
- [ ] 空原因、1 字或超过 100 字不可提交；取消弹窗不写数据。
- [ ] A 填写有效原因确认关闭，帖子 CLOSED，全部 PENDING 申请 REJECTED。
- [ ] B、C 刷新后看到正确状态，申请 note 显示管理员关闭原因，公开列表不再出现该帖。
- [ ] 已取消、已拒绝的申请状态与说明保持不变。
- [ ] 管理操作记录包含帖子 ID、标题、原因及时间，普通重启后仍存在。
- [ ] 对 RESOLVED/CLOSED 帖不能重复关闭，不产生重复日志。
- [ ] 与 B 确认交接/关闭同时操作，只有符合最新状态的一方成功，不出现 CLOSED 帖上仍有 PENDING 或已完成交接被改为拒绝。
- [ ] 快速重复点击只产生一次关闭及一条日志。
- [ ] 模拟日志写入失败时整笔关闭事务回滚，帖子、申请、日志不能部分成功。
- [ ] 操作中切后台，返回先刷新核对，不自动重复写入。
- [ ] 普通客户端调用 /api/admin 等未实现路径仍返回 404，不能通过改昵称获得管理权限。
